# PW-A7300

The A7300 build boots Sharp's Windows CE from the internal eMMC (read only) with in-flight skips and patches, as on the PW-SH2, and starts a plain CE desktop through `bstart`. This page covers what differs from the PW-SH2.

## Build

`BRAIN_MODEL=pwa7300` selects `pwa7300_ce_defconfig` (board `pwa7200`) in the U-Boot fork and names the wrapper `edna3exe.bin`. The loader is shared with the SH2 (`board/sharp/common/wince/`); A7300 values are Kconfig options in the defconfig, A7300-only code is in `board/sharp/pwa7200/`:

- No `CONFIG_VIDEO`. The [boot menu](reference.md#menu-and-u-boot-commands) and the CE load progress bar are drawn over EBOOT's 480x320 splash (PA 0x400FFC00) and written to the panel through the LCDIF with EBOOT's `MADCTL` 0x28 (`screen.c`), restoring the LCDIF registers each write changes.
- With `CONFIG_SHARP_WINCE`, upstream's early IO, SSP and CPU clock changes and the DUART remap of the PWM0/PWM1 pads are skipped; SSP clocks are set just before each MMC init.
- Register snapshot at entry, clock restore before the jump (`hwstate.c`).
- `SHARP_WINCE_BSP_ARGS=0x400F6C60` (SH2 0x400F3060); `SHARP_WINCE_SLOT_B` off, slot A only; `SHARP_WINCE_DEBUG_LOG` on.
- `bootcmd` (`SHARP_WINCE_BOOTCMD`) is `teprobe; brainmenu; savelog`. The keyboard (I2C0, 0x28, the SH2 controller) is started at boot as a console input, so the menu reads it with the PW-SH2's key codes, such as Enter (0x23). Escape is not yet tested. The keyboard reports presses, not held keys, so holding a key at power-on does nothing. `brainkey [ms]` remains: it logs each event and succeeds on Enter within 1 s.
- `teprobe` logs the panel TE pin (GPIO 4_16) as EBOOT left it, with tearing effect on and off.
- `CONFIG_CONSOLE_RECORD_OUT_SIZE=0x10000`, so `uboot.log` is complete.
- `nkpatch.c`: `load OFFSET LENGTH CRC32 PATH` records read `pwsh2-boot/PATH` into the image during the verify pass. The target must be zeroed (a skipped span) and the size and CRC-32 must match, or the region is cleared again and the section skipped.

CI builds it in the pinned container (`BRAIN_MODEL=pwa7300 sh build.sh out`) and the release card carries it as `EDNA3EXE.BIN`, with `EDNA3CFG.BIN` (flag `0x02` only, the config tested on the device).

## Patch Bundle

`tools/make-boot-nkp.mjs --skip --a7300-display HOOK_BIN` produces `bstart` and `a7300-display` sections. The skip list is marked tested for the A7300 main image (`894a227c...3d81`). `tools/check-a7300-image.mjs --a7300-display HOOK_BIN` applies the whole bundle offline and verifies every patched instruction.

`a7300-display` makes the panel take portrait-order writes (no MADCTL row/column exchange), turns tearing effect on, transposes each update into a buffer at PA 0x40110000, starts each transfer on the TE falling edge, and stops Sharp's TE watchdog re-initialising the panel. Its second entry replaces the driver's `MovePointer` so the old and new cursor areas are marked dirty and reach the panel. Build the hook with `ce/a7300-display/build.sh OUTPUT_DIRECTORY`, which also runs the transpose unit test.

For the A7300 and G5300 images, the `pwa7300` profile ([profiles/profiles.json](../profiles/README.md)) adds, in this order:

| Section or file | From |
| --- | --- |
| `a7300-display` | `build/a7300-display.bin` (`ce/a7300-display`) |
| `module gwes.dll`, `module ceshell.dll` | `binaries/pwa7300/`, a patched CE 6 build linked from Microsoft Platform Builder libraries. This `gwes.dll` draws a mouse cursor |
| `module ddraw_mx28.dll` | brain-display `pwa7300` |

`bstart.exe` and the display hook are appended after the image when they fit below `ulRAMStart`. Otherwise their data goes at the end of the largest skipped span and only the file table entries are appended. Bundles for images with room are unchanged.

## PW-G5300

The PW-G5300 (also `ED-NA3`, `EDNA3EXE.BIN`) runs the A7300 build unchanged. Its EBOOT (`V220`) differs from the A7300's (`V050`) only in a debug message line number, so the BSP arguments flag is the same. Its main image (`0844883d...a4ca`, 28,106,052 bytes, `nk-01acdd44`) has the same 158 modules at the same addresses; the drivers differ only in timestamps and debug GUIDs. It leaves 8,892 bytes below `ulRAMStart` (A7300 41,660), so `bstart` and the hook go in a skipped span. The display patch and the offline check accept both images. The bundle goes in `pwsh2-boot/nk-01acdd44/`; the A7300 keeps `pwsh2-boot/boot.nkp`. Booted with all 11 sections applied on 2026-11-04; the skip list is marked tested for this image.

## CE Programs

- `bstart`: copies `pwsh2-boot/Windows`, `pwsh2-boot/pwa7300/Windows` and `pwsh2-boot/Programs` at boot, registers `crash-handler`, restores brightness, idle timeouts and battery type (`power.txt`) and key/tap click settings, then stays resident to follow Volume & Sounds.
- `brain-control.cpl`: [Brain Control](brain-control.md), every setting in one applet. On the A7300: main and sub screen brightness, rotation, touchpad (`HKLM\Software\Brain\Touchpad`, reloaded through `PAD1:`), night light, sound, idle timeouts, battery type and CPU.
- Night light settings are in `HKLM\Software\Brain\NightLight`: `Enabled`, `Start` and `End` in minutes after midnight, `Transition` in minutes, `Strength` 10-100, and optional `WarmGreen`/`WarmBlue`, the panel gains at full warmth. [brain-display](https://github.com/grimace-sdk/brain-display) reads them; registry persistence keeps them past a restart.
- `crashlog.exe`: JIT debugger that logs to `pwsh2-boot/crash.log` instead of Sharp's reset screen.
- `Keymap.exe`: [UK keyboard layout](../ce/keymap/README.md#pw-a7300-and-pw-g5300). 機能 is Shift and 音声 is Fn, which gives digits and symbols, with the layer shown on the sub screen. Fn and the arrows change volume and main and sub screen brightness. The tray icon and Start > Programs > Keyboard Help show a keyboard map.
